[上一篇](/blog/site-ops-dashboard)说了选型：不要管家，要一面墙。这篇讲怎么钉。全部东西开源软件 + 一份 markdown，没有服务器，一台常开的 Mac 或小主机就够。

## 整体结构

三样东西，职责分明：

1. **Glance**（[github.com/glanceapp/glance](https://github.com/glanceapp/glance)）——开源仪表盘，单文件零依赖，负责渲染墙面
2. **markdown 账本**——唯一的数据源，一张表格记所有站：站点、上次维护日期、维护频率、下一步动作
3. **桥接脚本**——读账本、算出每个站多少天没动、按"最久没理"排序，喂给 Glance 的 custom API 组件

核心原则一句话：**账本只有一本，墙只是投影**。Glance 上什么都不写、什么都不改，面板只读渲染。两本账迟早打架，一本账永远不会。

## 第一步：装 Glance

```bash
brew install glance   # macOS
# 或按仓库 README 用 docker / 二进制
```

配置文件驱动，开机自启挂着即可。它自带 RSS、监控、书签一堆组件，但真正让它变成"你的"墙的是下面的桥接。

## 第二步：立一份 markdown 账本

我的账本就是一张普通表格，放在 git 里：

```markdown
| 站点 | 上次维护 | 频率(天) | 下一步动作 |
|---|---|---|---|
| 站A | 2026-10-20 | 14 | 拉GSC数据 |
| 站B | 2026-09-30 | 7 | 更新攻略内容 |
```

格式随便你定，能被脚本读就行。关键是**所有状态只记在这里**，别处出现第二份真相就是灾难的开始。

## 第三步：桥接脚本

思路极简，几十行：

1. 读账本表格，解析每行；
2. `今天 - 上次维护` 算出搁置天数，和频率比，得出"超期几天"；
3. 按"最久没理"降序排序，输出 JSON；
4. 用 Glance 的 `custom-api` 组件渲染，超期的标红。

Glance 配置里挂上这个脚本产生的接口（本地起个几十行的小 HTTP 服务，或直接生成静态 JSON 放 web 目录都行）：

```yaml
- type: custom-api
  title: 该干嘛
  cache: 15m
  url: http://127.0.0.1:9876/todos
```

`cache: 15m`——账本更新后一刻钟内墙自动对齐，不用任何同步操作。

## 我的四条设计原则

这些是踩坑之后留下的，比配置本身值钱：

1. **第一屏放"该干嘛"，不放监控曲线。** 站挂了别处也会知道；"哪个站被我冷落了"只有这面墙知道。
2. **点名字直接跳那个站的后台。** 省下的一步一天要走几十次。
3. **快过期的活单独一块，倒计时。** 内容站有窗口期，过窗即白干。
4. **不放会撒谎的灯。** 需要代理才能访问的后台不做"在线监控"——假红灯看多了人就不信墙了。仪表盘里最贵的是可信度。

## 第二台电脑怎么接

账本和配置都进 git。新机器 clone 下来跑一条初始化脚本：装 Glance、写 LaunchAgent 开机自启、配路径，完事。第三台第四台同理。
