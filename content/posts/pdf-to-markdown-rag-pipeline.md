做副业第二站时，我给自己换了个思路：**不从零写产品，从改造开源项目开始。**

理由很简单：副业最贵的资源是时间。从零写一个带用户系统、支付、订阅的产品至少一两个月，而社区里大量 MIT 协议的开源项目已经把这些都做好了——法律允许商用，义务只是保留版权声明。你要做的，是把它改造成「能收钱的商业产品」。

这次我验证的就是这条路。

## 选品：AI 原生格式背后的刚需

选品阶段我盯上了「文档转 Markdown」这个需求，原因有两个。

第一，**Markdown 是 AI 时代的文档标准答案**：主流模型都在它上训练，结构信息完整保留，对 token 也友好。做 RAG、做知识库的人都知道，把 PDF 直接丢进向量库基本等于喂垃圾——表格乱掉、扫描件空白、阅读顺序错乱，这些痛点真实存在了半年。

第二，这个需求**巨头看不上**：头部搜索结果全是 pdf24、smallpdf 的内页，独立站机会很大。

方向定了：做一个文档转 Markdown 的工具站，按页收费。

## 改造：买来的时间花在哪

GitHub 上有个开源项目（MIT 协议，3 万多个文件）把最难啃的部分都做好了：Next.js 全栈、用户系统、订阅支付、多语言。fork 过来，5 天做了这些事：

- **换品牌**：全局色相替换 + logo/文案，339 处颜色类一次脚本跑完；
- **换支付**：上游的 Stripe 通道换成 Creem（记录商户，税务合规都归它管）；
- **接 AI**：文档解析对接 Mistral OCR，转出来的 Markdown 每个内容块带置信度评分——做 RAG 的可以按分数过滤低质量块，不把垃圾喂进向量库；
- **修坑**：上游代码一半的坑「本地能跑、上线就炸」，一个一个补。

## 上线：钱怎么收

计费按页：1 积分 = 1 页，转换失败不扣钱；注册送 30 积分，够先验证质量再决定付不付费。订阅或积分包都行，付费用户带 API。

上线后的验证比想象中顺利：6 个落地页被 Google 全量收录；支付到账、退款回收这些真金白银的链路，用真实支付在环境里跑通了完整往返——包括退款后自动扣回赠送积分这种细节。

## 一个值得记住的坑

最大的坑不在代码，在「残留」：基于开源项目改造，换品牌时漏改了几处上游文案——连定价页展示的价格都是模板里的旧数字，我自己都是付款测试时才发现。这种东西用户不会告诉你，但一定在悄悄消耗信任。**改造类项目上线前，值得做一次全页面逐字过一遍的笨功夫。**

## 这条路走通了吗

5 天，一个能收钱的商业网站，验证成本极低。副业的本质是时间换钱，而「改造开源项目」本质上是把别人花一年写的地基，变成你一星期的装修——这中间的差价，就是独立开发者的利润空间。

第二个站已就位，接下来就是写内容、看数据、等第一个真实付费用户。
