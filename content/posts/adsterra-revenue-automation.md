[Build in Public 的第一篇](/blog/hello-build-in-public)立了个 flag：赚没赚到钱全部公开。这周把这条公开链路里最人工的两环改成了全自动。这篇是复盘：为什么做、怎么取舍、现在账是怎么算的。

## 两件重复劳动

给游戏攻略站挂 Adsterra 广告有一阵子了，两件事反复消耗我：

**第一，接入靠 Agent 开浏览器。** 每个新站挂广告，都是让 AI Agent 用浏览器进 Adsterra 后台：打开网站列表、找目标站、展开单元、点 Get code、从弹窗里把广告代码挖出来。一轮下来浏览器快照刷几十屏，token 烧得心疼，点错界面还得重来。

**第二，看收益靠记性。** 广告挂上去要等一两天才出量，然后开后台看 impressions、手动记进账本、重新生成[公开的数据大盘](/dashboard)。步骤不难，全靠想起来做——结果大盘经常是旧的，flag 打了折扣。

两件事的共同解法：**把"进后台"变成"查 API"，把"记得做"变成"定时做"**。

## 为什么不用 B 方案

第一个念头是让浏览器自动化定时跑：每周自动进后台把收益页面截下来解析。这条路我直接否了——Adsterra 对无头浏览器有官方反自动化检测，请求直接返回 0/403，抓回来的是空数据。为了绕检测再去维护一套伪装，得不偿失。

收益记账继续手动、加个日历提醒？提醒只能解决"忘记"，解决不了"麻烦"。麻烦的流程靠提醒，最后只会变成"提醒了也不想干"。

正确的路径还是先查官方文档——[Publisher API](https://docs.adsterratools.com/public/v3/publishers-api) 是有的。这里有个挖文档的技巧：文档页是 Stoplight 单页应用，直接抓 HTML 什么都没有，但 OpenAPI spec 的路径就藏在它加载的 JS chunk 里，一条 curl 拿到完整接口定义。

API 的能力边界也清楚了：GET-only 五个端点，能列网站、列广告单元、按日/站/单元拉 impressions、点击、CPM、收益；不能加站、不能建单元、**拿不到广告代码**。

所以解法不是"API 替代浏览器"，而是把浏览器降级成白名单：**加站、建单元、取码，一个站一生各一次**。之后的盘点、验证、看收益，全是 curl。

## 关键实现

**1. API 通道包成一个脚本。** 一个 bash 脚本四个子命令（`domains` / `placements` / `placements-all` / `stats`），curl + jq 零依赖，输出默认裁剪好——盘点全账号二十来个站、五十来个单元，两条命令。实际用下来还有个惊喜：横幅单元的命名直接带尺寸（`728x90_1`、`300x250_1`），连"这个单元多大"都不用进后台确认。

**2. 取到的码落盘复用。** 后台取到广告代码，立即回写进站点仓库的文档（单元名/格式/尺寸/key/日期）。广告代码本来就随页面源码公开，落盘没有泄露问题——换来的是同一个站下次加广告位，后台一次都不用开。

**3. 收益回填复用现成的账本。** 我的账本是一个私密 JSON，生成器从它产出两样东西：本地开的私密大盘、博客公开页用的裁剪 JSON（[这篇](/blog/build-blog-from-scratch)写过双层渲染）。所以这次没造新面板，账本里加一个 `income-adsterra` 指标就完事。两条口径写进了数据文件本身、跟着一起公开：收益明细不外泄，公开页只有折算后的合计；广告平台报的是"赚得"，实际打款有 $100 起付线，两回事。

**4. 调度避开统计延迟。** 广告平台的数据有约一天滞后，当天数字第二天才齐。定时任务设在每周一早上，拉"上个自然月（已定稿）+ 当前月（覆盖刷新）"，跑完自动入库、重生成大盘、部署、验证，最后给我一句话汇报。选周一还因为周末刚走完，整周数据正好看。

## 算账环节

现在的接入流程：

```
API 盘点 → 单元码落盘了？直接用 → 缺码才进一次后台 → 取到码落盘复用
```

看收益这件事，从工作里删掉了。每周一早上自动跑：

```
拉 API 日收益按月求和 → 回填账本 → 重新生成大盘 → git 入库 → 部署 → curl 验证 → 一句话汇报
```

说实话，广告目前的收益还很小——上线十天，全账号个位数美金，在[大盘](/dashboard)总收入里就是个零头，大头还是订阅和 AdSense。但这笔钱是第一个全自动回填的收入源：从这周起，大盘上那个数字每周一自己长，不需要我做任何事。

## 踩坑清单

**token 写死进脚本，被自家红线拦了。** 为了零配置，我一开始把 API token 直接写在脚本里，本机确实一步到位。第二天往个人 skills 仓库推的时候，撞上仓库 README 里自己定的红线：API token 永不入仓。私有仓库，"就这一次"？还是改了——token 挪进 `~/.keys/`（600 权限），脚本按 `--参数` > 环境变量 > 仓库 `.env` > 密钥文件的顺序解析，推送前加一道密钥残留扫描。结果同机依赖这个脚本的几个定时任务一行没改，照常跑。

**实测报文和文档示例不一致。** 错误返回的 JSON 结构和 spec 里的示例对不上，报错处理按 HTTP 状态码走，别解析报文结构。

**代理结论不能跨通道迁移。** 同一台机器，Google 系服务必须挂代理，Adsterra 的 API 挂代理反而直接失败——每个通道的可达性只能逐个实测，然后把结论写进通道自己的文档。

**无头浏览器 0/403 是检测，不是故障。** 之前排查广告位总拿无头浏览器打开页面，invoke.js 请求被拦就以为接入坏了。那是官方反自动化，出量验证以 API 统计为准。

## 后续

按站拆收益先观察有没有需求，暂时全账号合计就够了。"账本 → 双层渲染"这套管道用起来比想象中顺，考虑整理成模板开源。下一篇聊聊攻略站矩阵的维护流水线（GSC 拉数 → 意图分析 → 内容执行）自动化到什么程度了。
