[Build in Public 的第一篇](/blog/hello-build-in-public)说过要把赚没赚到钱全部公开。这周把公开链条里最人工的两环去掉了：给攻略站挂 Adsterra 广告的接入流程，和广告收益的记账流程。

## 先查官方 API，别急着写浏览器自动化

之前的接入流程：Agent 用浏览器进 Adsterra 后台，打开网站列表、找站、点单元、Get code、从弹窗里挖广告代码。一轮下来浏览器快照刷几十屏，token 烧得心疼。

动手自动化之前先查了官方文档——[Publisher API](https://docs.adsterratools.com/public/v3/publishers-api) 是有的，GET-only 五个端点：列网站、列广告单元、按日/站/单元拉 impressions、点击、CPM、收益。边界也清楚：加站、建单元、**拿广告代码**都不行。

所以解法不是"API 替代浏览器"，而是把浏览器降级成白名单：加站、建单元、取码，一个站一生各一次；之后的盘点和看收益全是 curl。

实际盘下来有惊喜：账号下二十来个站、五十来个单元两条命令拉完，横幅单元命名直接带尺寸（`728x90_1`、`300x250_1`），连"这单元多大"都不用进后台看。取到的码落盘进站点仓库，下回加位直接引用，后台一次不开。

顺带一个挖文档的技巧：这文档页是 Stoplight 单页应用，直接抓 HTML 什么都没有，但 spec 文件路径就藏在它加载的 JS chunk 里——翻出来一条 curl 拿到完整 OpenAPI 定义。

## 收益管道：账本加一个字段而已

收益公开的管道之前已经搭好：一个私密 JSON 账本，生成器产出两样东西——本地开的私密大盘、博客公开页用的裁剪 JSON（[这篇](/blog/build-blog-from-scratch)写过）。所以这次没新造面板，账本里加一个 `income-adsterra` 指标就完事。

两条口径先声明在数据文件里，跟着数据一起公开：收益明细不外泄，公开页只有折算后的合计；广告平台报的是"赚得"，实际打款有 $100 起付线，两回事。

## 被自家红线拦了一下

API token 在后台生成。为了零配置，我一开始把它写死在脚本里——本机确实一步到位。

第二天往个人 skills 仓库推的时候，撞上仓库 README 里自己定的红线：**API token 永不入仓**。私有仓库，"就这一次"？

还是改了。token 挪进 `~/.keys/`（600 权限），脚本按 `--参数` > 环境变量 > 仓库 `.env` > 密钥文件的顺序解析，推送前加一道密钥残留扫描。本机依旧零配置，同机依赖这个脚本的几个定时任务一行没改，照常跑。

## 现在的流程

```
API 盘点 → 单元码落盘了？直接用 → 缺码才进一次后台 → 取到码落盘复用
```

看收益不用做了。每周一早上自动跑：

```
拉 API 日收益按月求和 → 回填账本 → 重新生成大盘 → git 入库 → 部署 → curl 验证 → 一句话汇报
```

调度设在周一是有意的：平台统计有约一天延迟，周一正好覆盖刚结束的完整一周，上月数据也已定稿。上线十天，全账号广告收益个位数美金——从这周起[大盘](/dashboard)上的数字每周自己长。

## 其他踩坑

- 实测报文和文档示例对不上（错误体结构不一致），错误处理按 HTTP 状态码走，别解析报文
- 代理结论不能跨通道迁移：同一台机器，GSC 必须挂代理，Adsterra 挂代理反而直接失败
- 无头浏览器会被 Adsterra 反自动化拦截（请求 0/403），那是官方检测不是接入故障，出量验证以 API 统计为准
