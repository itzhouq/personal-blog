我一直觉得自己的标题还凑合——《给广告收益装上自动挡：Adsterra API 化改造复盘》《用 MCP 让 AI 读你的微信群消息：本地解密 + AI 总结全流程》，对仗工整，信息完整。

直到今天我让 AI 拿 X 上的实测数据把这些标题挨个对照了一遍。结论不太好听：**8 篇里 6 篇要重写**，问题出在同一个地方——我的标题都是「汇报体」。

## 数据先说话

X 官方给创作者的 SOP 里有一条叫「标题定生死」：长文在时间线里只露标题和封面，官方原话级建议是**把标题当推文钩子写，别当书章节名写**。

一组实测数据更直接：数字型钩子的平均浏览量约是提问式的 3.5 倍（5.7 万 vs 1.6 万，280 条长文样本）。带具体金额的「How I made X」类标题，比抽象的「How I did X」表现翻倍。Build in Public 垂类还有个现成公式：**数字 + 时间 + 反直觉结论**。

拿这把尺子量我的旧标题：

- 「给广告收益装上自动挡：Adsterra API 化改造复盘」——比喻不错，但「复盘」是台账尾缀，说我在干活，没说你能得到什么；
- 「小工具，解决日常小麻烦：我的纯前端工具集上线了」——最典型。摘要里明明有「14 个」这个数字，标题里一个都没有。

而真正及格的两篇，恰好是反直觉+有人设的：「个人工作台很火，但我给自己写了面「站况墙」」「不买服务器的独立开发者：开一个「穷鬼套餐」系列」。规律很诚实：**像跟朋友说话的标题活了，像写工作总结的标题死了**。

## 办法不是「让 AI 起个好标题」

第一反应是以后写完让 AI 自由发挥起三个标题。试了试就放弃了：AI 起标题有两个毛病，爱铺垫（「在这篇文章里，我将分享……」），爱骑墙（什么钩子都想要，结果什么都不是）。

靠谱的做法是**把「取标题」变成一道有检查项的工序**，像 code review 一样跑：

1. **正文写完后产 3 个候选**，按三个公式混搭——`数字/金额 + 时间 + 反直觉结论`（主推）、`反直觉观点 + 人设钩子`、`具体利益 + 活人场景`；
2. **硬性检查**：至少一个具体数字（实在没有就必有反直觉观点）；禁用「复盘 / 上线了 / 全流程」这类台账尾缀单独作标题落点；读起来像跟朋友说这事，不像述职；核心关键词保留在标题或摘要里兜 SEO；中文别超过 22 字；
3. **选 1 留 1**：落选的好标题不扔，留作发 X 时的卫星推钩子——长文在 X 上靠周边推文引流，标题和钩子本来就是同一套规则。

这道工序我写进了自己的 agent 工作流规范里，以后每次写文章，AI 会自动走这一步，不需要我记得。

## 执行：6 篇旧文回炉

规则定完，拿旧文开刀。举两组对照：

- 「小工具，解决日常小麻烦：我的纯前端工具集上线了」→「**14 个小工具，0 上传：我给自己写的在线工具箱**」（数字前置，0 上传是真实卖点）；
- 「给广告收益装上自动挡：Adsterra API 化改造复盘」→「**看收益这件事，我从工作清单里删掉了**」（直接说利益，Adsterra 关键词挪进摘要兜搜索）。

slug 和链接全部没动，只改 frontmatter，站内互链不受影响。5 张封面按新标题重新生成，公众号草稿箱里 4 篇对应草稿也删旧推新，一次同步。
