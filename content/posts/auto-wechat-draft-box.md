我的内容主阵地是博客，但读者在微信里。每写完一篇技术复盘，想到还要打开公众号后台、新建图文、把 Markdown 重新排一遍版、外链一个个改成能看的样式、传封面、调摘要——写文章的热情瞬间就凉了。

今天把这条路彻底打通了：**一条命令，博客的 Markdown 自动变成公众号草稿箱里一篇排好版的图文**，我只负责最后看一眼、点发布。这篇记录完整方案，以及三个官方文档里查不到、只能靠实测踩出来的坑。

## 先定原则：只进草稿箱，永不自动发布

做之前先想清楚边界。公众号是个人订阅号，官方接口的现状是：

- 素材管理（传图、传封面）✅ 可用
- 草稿箱（新建草稿、查草稿、删草稿）✅ 可用
- 发布接口 freepublish ❌ 2025 年 7 月起对个人主体关闭

这个"关闭"反而成全了我：**自动发布本来就不该做**。公众号平台在打击 AI 托管运营，全自动群发风险高；而"机器做排版，人做最终确认和发布"既合规又符合我的工作流——草稿箱就是这条流水线的天然终点。

所以原则定为三条：只用官方 API，不模拟登录；只调草稿箱，不碰发布；排版确认和点发布永远由人完成。零封号风险，心里踏实。

## 中间踩了个认知弯路

动手前我先调研了几个现成轮子。其中最热的一个开源社媒运营工具，公众号能力默认走 Playwright 驱动公众号后台网页、扫码登录、模拟操作建草稿。能用，但依赖浏览器选择器——平台页面一改版就挂，而且"程序操作后台"本身就踩在风控的边上。

看完它的源码我发现一个有意思的事：它最终调的也是后台的建草稿接口，而且官方 API 是它的回退方案。**它把官方 API 当备胎，我把官方 API 当主路**——个人订阅号草稿箱 API 可用，为什么要绕浏览器？这条主路后来被验证是对的，全程没出过一次权限问题。

## 整条链路长什么样

工具就是一个几百行的 Python CLI，核心流程四步：

```
Markdown → 转成微信编辑器认的内联样式 HTML → 传封面和正文图 → 调草稿箱接口
```

看起来简单，但公众号的编辑器是个"只会内联 style 的渲染器"，每一步都有平台规则要适配：

**排版**。所有元素必须内联样式：正文 15.5px、行高 1.8，代码块用深色背景加语法高亮（pygments 直接输出内联色值），标题加粗居左。转换完我用浏览器套一个手机壳预览，和草稿箱里的实际效果基本一致。

**链接**。这是最反直觉的一条：未认证账号正文里的超链接是不可点击的，微信会直接把 href 剥掉。一开始我想当然地保留了 `<a>` 标签，后来发现读者看到的只是一段变色的文字。解法是把所有外链统一收进文末的「参考链接」清单，正文里链接文字保留变色——能读，想点的人去文末找。

**图片**。正文里的外链图片发布后会失效，必须走素材接口转存成微信自己的图床链接。好在我的文章目前以纯文字为主，这段逻辑先备着。

**闭环**。文末自动追加一张出处卡片："本文首发于我的博客 itzhouq.cn"。公众号是分发位，博客是信任位，读者要顺着链接能回来——这是个人 IP 这盘棋里最基本的规则。

## 三个文档里查不到的坑

以上都是正常工程。真正的时间花在三个坑上，官方文档一个字都没提。

**坑一：JSON 里的中文会被微信"吃掉"转义。** 第一次推送，接口报 `45110 author size out of limit`——作者名超长。可我传的作者只有三个汉字，怎么可能超长？把请求原样打出来才看懂：Python 的 HTTP 库默认把 JSON 序列化成 `\u98ce\u98de\u626c` 这种转义形式，标准 JSON 解析器都认，**但微信后端不解码，直接把 `\u98ce\u98de\u626c` 这 12 个字符当成了作者名**。三个汉字变十二个"字符"，超长报错。解法是序列化时关掉转义、显式按 UTF-8 编码发原始字节。修完之后，草稿箱里躺着的草稿标题再也不是 `\u8c03\u8bd5` 这种天书了。

**坑二：作者名限 8 字符。** 这个好查，但组合上一条就成了烟雾弹——先以为是字数问题，改短了还报错，才知道是转义问题叠加字数限制。

**坑三：一张封面的素材 ID 只能用一次。** 测试时复用同一张封面建第二个草稿，报 media_id 无效。按文档理解永久素材应该可以反复引用，实测就是不行。解法简单粗暴：每次推送都重新传一张封面，不做复用。

还有一个环境认知上的收获：我一直以为自己"没有公网 IP"所以填不了接口白名单。实际上白名单要填的是**网络出口 IP**——我开着代理，国内流量走的是直连规则，微信看到的是我家宽带的真实出口。填对了它，一次过。这个误区值得单独记一笔：**所谓"没有公网 IP"的机器，联网就有出口 IP，白名单要的从来只是后者**。

## 现在的发布流程

写完文章后，我的动作变成了：

1. 跑一条命令，Markdown 变草稿（封面自动生成或从封面目录自动取用，封面这套后面单独写一篇）；
2. 打开公众号后台草稿箱，看一眼排版；
3. 点发布。

写文章一小时，分发十分钟。下一批存量文章会按这个节奏陆续推进草稿箱。下一篇聊聊封面这件"小事"是怎么从"自动生成的图太丑"做成一个带独立子域名的在线工具的。
