## 起因：一个还没被中文互联网反应过来的词

事情要从 10 月 20 号晚上说起。我每天有个固定动作：让自动化流程帮我盯一圈 AI 圈的动态——Hacker News、GitHub 趋势、一些信息源，凡是冒出来的新词、新项目，都会推给我一份摘要。

那天晚上推过来的是 DeepSeek 前一天刚开源的推理框架。HN 上 2100+ 分，Google Trends 的搜索热度已经在同类的开源推理框架 vllm 之上。

真正让我坐直了的不是这个词有多火，而是我做了个交叉检查：**拿这个词去中文搜索引擎里搜，几乎是空白**。没有像样的中文介绍文章，没有部署教程，没有成本对比。一个日搜索热度已经超过成熟项目的词，中文内容位还空着。

这种窗口不会一直开着。热点词的生命周期一般是几周到几个月，等中文科技媒体反应过来、等第一批教程出现，后来者就只能跟几十篇同质文章抢排名。抢先发，等热度爬坡的时候你已经在搜索结果前排了。

作为一个 10 年的后端，我太清楚这事拖不得——但按老办法，从买域名、搭框架、写内容到部署上线，起码磨一个周末。好在这两年我的工作方式变了。

## 决策：不做工具，先占内容位

先说清楚我为什么选"做内容站"而不是"做个工具"。

做工具是我的老路：我的[工具箱](https://tools.itzhouq.cn)就是这么来的。但工具的冷启动成本高——没流量的时候没人用，没人用的时候就一直没流量。而一个"新词 + 内容空白"的机会，天然自带搜索流量，你要做的只是在用户搜索的时候刚好在结果里。

所以路线定为两条腿：

1. **工具卡**：在我的工具箱里加一张工具卡（当天就上了线），算是一个展示位；
2. **独立域名**：做一个小而完整的双语内容站，当我的"新词实验田"——验证这个打法能不能跑通，跑通了就复制。

选域名花了点功夫。我让 Agent 拉了一批可注册的域名，逐个核对，标准就三条：读起来像 AI 主题的站、对中文受众友好、**之前没有沉淀流量**（老域名可能背着搜索引擎的处罚历史，捡漏有风险）。20 个候选看下来，定了一个，Cloudflare 成本价注册，$10.46 一年。

到这里，决策花掉的时间不到晚饭的工夫。搁在以前，光是"要不要为一个小词单独买域名"我就会犹豫一晚上。现在我的原则是：**实验的单位成本压到一顿饭钱，执行就不再犹豫**。

## 建站：AI Agent 把"一个周末"压成"一下午"

技术选型没什么可纠结的：Next.js 16 静态导出 + Tailwind，部署到 Cloudflare Pages——和我博客、工具箱同一套栈，坑都是踩熟了的。

真正花心思的是内容结构。这个站没打算糊一篇长文了事，而是围绕这个词的用户搜索意图铺了一张网：

- 这是什么 / 和 vllm 比怎么样 / 和 sglang 比怎么样（对比词是搜索大头）
- 硬件要求 / 安装教程 / 自托管还是调 API（动手意图词）
- 投机解码、结构化输出、基准测试解读（进阶词）
- 还有一页**双语成本计算器**，默认价格直接用官方披露价

中文英文各一套，一共 10×2 个内页，加双语首页 hub，用 hreflang 互链。所有数据不是拍脑袋——当时是多源调研凑的：官方对标里 GB200 上和 vLLM 的差距约 6%，前缀缓存命中率 96%，投机解码单卡 14K tokens/s。这些数字都进了内页。

这一整套，从建仓到内容初稿，是 Agent 一口气管完的。我做的事是定结构、盯数据来源、把 AI 写得"太规整"的句子改得像人话。**10 个内页的手工成本大概是我两三个晚上，Agent 把它压成了一下午**——这就是我一直在说的"AI 杠杆"：不是 AI 替你思考选题和判断，而是替你把想清楚的东西执行出来。

## 翻车两次：教训都很贵

如果文章到这里结束，那就太像广告了。真实情况是：**部署环节我连翻两次车**。

**第一次：API 限流**。连续发了好几次部署命令，Cloudflare API 直接限流，错误码 10429。最难受的是连 GET 请求都被限——连"看一下部署状态"都做不了。限流窗口 20 分钟以上，只能退避重试干等。教训：批量操作要带节奏，别把部署命令当 while 循环跑。

**第二次：OAuth 过期，而且是被我自己弄坏的**。wrangler 的登录态过期了，我下意识想"手动 curl 一下刷新接口"，结果这一下触发了 token 轮换——旧的作废，新的发给了非交互环境里没有浏览器的我。当场锁死，本地没法 login（login 要弹浏览器），自动化流程全线卡住。

最后是换了一条彻底的路：**建了一个权限最小化的 API Token**，自动化里一律走 Token，永远不碰 wrangler 的交互式 OAuth。这个 Token 存在本机密钥目录里，从此部署链路变成三条固定命令，不再依赖任何"登录态"这种玄学。

这两次翻车加起来耗掉小一个小时，但值——现在这条"API Token + 固定命令"的部署链路已经沉淀成文档，后面所有站点都受益。**失败本身也是产出，前提是你把它记下来。**

## 收尾：域名绑定到收录提交，全程没打开过控制台

部署通了之后，剩下的环节顺利得有点无聊：

- **域名绑定**：走 Cloudflare API，把 apex 和 www 挂到 Pages 项目上，删掉旧解析，建 CNAME 指向 pages.dev，开橙云。2 分钟生效。
- **验证**：生产环境 11 个 URL 全部返回 200，sitemap 24 个 URL。
- **收录提交**：晚上 10 点 45，挑了 8 条高优先级 URL 手动请求编入索引——选词逻辑是头部词 → 对比词 → 部署/成本意图词 → 英文同词。

从晚上刷到热词，到站上线、域名绑定、收录提交，全程一天。中间还穿插着带娃、给[公众号那边的穷鬼套餐系列](https://itzhouq.cn/blog/cloudflare-free-series-01-map)写稿这些事。以前我会觉得"一天上线一个站"是自媒体标题党，现在它就是我的正常节奏——不是我变强了，是我把重复的部分全部交给了 Agent。

## 算账：花了什么，图什么

按惯例，数据公开：

- **成本**：域名 $10.46（一年），Agent 调用的 token 费用几块钱人民币，没买服务器（静态托管免费额度内）。
- **产出**：1 个独立域名 + 20 个内容页 + 1 张工具卡 + 1 份可复用的部署文档。
- **预期**：这是个实验田，我给它 1-3 个月。如果搜索流量起来，变现路径优先接 GPU 云服务的 affiliate（教程站的读者天然有租卡需求），广告兜底。如果 3 个月数据不行，我会在博客里写一篇《为什么死了》——这个号说好了，失败也发。

更重要的产出其实不在钱上：**"新词雷达 → 抢内容位 → Agent 一天建站"这条流水线本身验证通了**。下一个词冒出来的时候，我不需要重新发明流程，把词换掉就行。这才是我真正在 build 的东西——不是某个站，是这套打法。
