微信群加得越来越多，每天消息上千条，真正有价值的淹没在闲聊和表情包里。手动翻一遍所有群要半小时，还不一定抓到重点。

前段时间做 MCP（Model Context Protocol）工具上瘾——[archery-mcp]({{< ref "archery-mcp-open-source.md" >}}) 让 AI 只读生产库，grafana-mcp 让 AI 看监控（方案整理中，后续分享）——自然就想到：**能不能让 AI 直接读我的微信群消息，帮我总结？**

答案是可以，而且效果比预期好得多。这篇聊聊完整的技术方案和思路。

## 核心思路

整个链路分三层：

```
微信本地加密数据库 → 解密成明文 SQLite → MCP Server 暴露给 AI → AI 总结/搜索/分析
```

关键设计原则：**全程本地运行，数据不上任何云**。MCP 是 stdio 本地通信，AI 只能读到你本机解密的数据。

## 第一层：微信本地数据库解密

### 微信 4.x 的加密方案

macOS 版微信 4.x（WCDB）用 SQLCipher 4 加密本地数据库，加密链路：

```
passphrase（32B 随机密钥）
  → PBKDF2-HMAC-SHA512（256000 轮迭代）
  → enc_key（AES-256 页密钥）
```

passphrase 存在微信进程内存里，数据库文件在磁盘上是一堆 `message_N.db`、`contact.db`、`session.db` 等加密 SQLite。

### 密钥提取

passphrase 需要从微信进程内存中提取。思路是用 LLDB（macOS 自带调试器）attach 到微信进程，在 SQLCipher 打开数据库的断点处抓取 passphrase 参数。

**这步需要 sudo 权限**，因为调试其他进程需要 root。这里有个坑：sudo 运行时写出的密钥文件属主是 root，普通用户读不了。解决方法是在写文件后用 `SUDO_USER` 环境变量 chown 回真实用户。

### 解密

拿到 passphrase 后，用 SQLCipher 打开加密库，导出为明文 SQLite。微信 4.x 有 24 个加密库（message_0/1/2.db、contact.db、session.db、message_fts.db 等），全部解密后约 200-500MB。

## 第二层：MCP Server

### 为什么用 MCP

MCP（Model Context Protocol）是 Anthropic 推的协议，让 AI 通过标准化接口调用外部工具。简单说就是：**AI 想读什么数据，MCP Server 给它提供工具函数**。

我用了 `fastmcp` 框架（Python），一个 `@mcp.tool` 装饰器就能把 Python 函数暴露成 AI 可调用的工具。AI 端（ZCode/Claude Desktop/Cursor）配置一行 JSON 就接入了。

### 14 个工具

最终暴露了 14 个 MCP 工具：

| 类别 | 工具 | 说明 |
|------|------|------|
| 系统 | `health` / `force_sync` | 自诊断 / 强制同步 |
| 会话 | `get_recent_sessions` / `get_contacts` | 最近会话 / 联系人搜索 |
| 聊天记录 | `get_chat_history` | 完整记录（自动解码压缩内容和卡片消息） |
| ⭐ 群总结 | `get_group_digest` / `batch_group_digest` | 单群/批量群清洗发言流 |
| 群分析 | `get_group_stats` / `get_group_members` | 活跃度排行 / 成员列表 |
| 搜索 | `search_messages` / `hot_keywords` | 关键词搜索 / 热词趋势 |
| 其他 | `get_sns_timeline` / `get_favorites` / `get_filehelper_batches` | 朋友圈 / 收藏 / 文件助手批次 |

最核心的是 `get_group_digest`——它返回的不是原始消息，而是**清洗后的发言流**：

- 系统消息（入群退群、红包领取）自动过滤
- 图片消息 → `[图片]` 占位
- 文章卡片 → 标题 + 链接
- 语音/视频 → `[语音]` / `[视频]` 占位
- 压缩内容（zstd）自动解压解码

这样 AI 拿到的是干净的文本流，直接就能总结，不用处理各种消息格式的噪音。

### 跨库查询的坑

微信 4.x 有个设计：**同一个群的消息按时间分段分布在多个 message_N.db 里**。比如一个活跃群 3000 条消息，可能 message_0.db 存了最早的 1000 条，message_2.db 存了最近的 2000 条。

最初我的查询逻辑只找第一个命中的库（message_0.db，含最早数据），结果 AI 总结出来的都是几个月前的旧消息。修复方法是遍历所有库取数据，按时间排序合并。

## 第三层：AI 总结

### 效果演示

实际测试了一个 3417 条消息的技术交流群，近一个月的数据：

1. 调用 `get_group_digest(group="某交流群", hours=720, limit=500)` 拉取清洗发言流
2. AI 自动生成结构化总结：
   - **活跃度排行**：谁发言最多、谁是核心输出者
   - **投资策略讨论**：价值投资 vs 趋势交易、板块轮动逻辑
   - **求职招聘信息**：某公司急招量化岗、内推线索
   - **副业探索**：自媒体、知识付费、跨境电商
   - **人生哲学**：复旦退学创业、35 岁焦虑、财务自由标准

3000 多条消息压缩成约 800 字结构化总结，核心信息覆盖率约 95%。

### 批量多群速览

新增的 `batch_group_digest` 工具可以一次拉多个群：

```
batch_group_digest(min_unread=5, hours=24, max_groups=10)
```

AI 自动按未读数排序，优先处理最活跃的群，每个群输出一个 30 秒速览卡片。10 个群 2000 条消息，3 分钟就能读完。

### 热词趋势

`hot_keywords` 工具统计所有聊天的高频词，能发现跨群共现话题。比如 "AI" 和 "大模型" 同时在 3+ 个群高频出现，说明这个话题最近确实很热。

中文分词用简单 2-gram（不做 NLP），准确度够用——趋势发现不需要精确分词，只要频率对比。

## 提示词模板

配套写了几个提示词模板，让 AI 按固定流程操作：

- **每日群消息总结**：自动筛选未读 >20 的群，逐个总结
- **单群深度分析**：3 天深度挖掘一个群
- **跨群关键词搜索**：追踪一个话题在所有群的讨论
- **批量多群速览**：一次调用快速浏览所有群
- **热词趋势分析**：本周热词榜 + 主题归类 + 行动建议

## 技术栈

- **解密**：SQLCipher 4 + LLDB 密钥提取
- **MCP Server**：Python + fastmcp（stdio 传输）
- **AI 客户端**：ZCode（已配置 MCP 接入）
- **数据**：全程本地，不上云

## 复盘

### 做对了什么

1. **MCP 架构选对了**：stdio 本地通信，数据不出本机，隐私安全
2. **清洗层设计**：digest 不是原始数据而是清洗后的发言流，AI 处理效率高 10 倍
3. **增量同步 + 60s 节流**：查询时自动检测源库变化，有变化才重解密，日常使用无感
4. **提示词模板分离**：不同场景不同模板，可复用可迭代

### 踩的坑

1. **sudo 文件权限**：LLDB 提取密钥要 sudo，写出的文件属主 root，普通用户读不了
2. **FTS 虚拟表**：微信用自研分词器 MMFtsTokenizer，PRAGMA table_info 直接报错
3. **跨库消息分布**：同一个群的消息按时间分段在多个库里，只查第一个库会拿到旧数据
4. **压缩内容**：微信 4.x 部分消息用 zstd 压缩，不解压搜不到也读不了

### 不开源的取舍

说实话，不开源有点可惜——这套方案的完整度已经很高了（14 个工具、53 个测试、跨库查询、增量同步）。但法律风险是实打实的，chatlog/PyWxDump 的前车之鉴就在那里。
